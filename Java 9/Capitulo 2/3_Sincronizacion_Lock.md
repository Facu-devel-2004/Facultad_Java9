## Lock() Funcion
Java cuenta con otro mecanismo para sincronizar bloques de codigo mas flexible y potente que "synchronized". La interfaz Lock y las clases que la implementan.
Las ventajas de usar Lock es que solo tengo el control sobre un bloque sincronizado de forma estructurada. Sin embargo, la interfaz Lock te permite lograr estructuras mas complejas para implementar tu seccion critica. La interfaz Lockofrece funcionalidades adicionales frente a la palabra synchronized, una de esas se implementa usando el metodo "tryLock()", este metodo intenta obtener el control del Lock, y si no puede porque otro hilo esta usando devuelve False osea NO se queda esperando "Es como decir que, si un hilo ve que esta bloqueado porque otro esata ejecutando el bloque, no te quedes ahi y ve por otro bloque".

En el caso de tener un Hilo (A) en un bloque de codigo pero queda suspendido porque el Hilo (B) esta ejecutandolo y este debera terminar su ejecucion, con tryLock() podre ver si el bloque esta siendo usado o no.
La interfaz ReadWriteLock permite separar las operaciones de lectura y escritura con varios lectores y solo un modificador, osea muchos hilos pueden leer al mismo tiempo pero si uno va a escribir entonces el resto se bloquea. 

El constructor de la clase Lock admite un parametro booleano llamado "fair", este parametro permite controlar su comportamiento. El valor False es el valor predeterminado y se llama "non-fai mode", en este modo si algunos hilos estan esperando un bloqueo y el bloqueo tienen que seleccionar a uno de estos para obtener acceso a la seccion critica, selecciona aleatoriamente uno de ellos. El valor True se llama "fair mode", si algunos hilos estan esperando un bloqueo y el bloqueo tiene que seleccionar uno para darle acceso a la seccion critica, selecciona el hilo que estuvo esperando por mas tiempo. (Recordar, esta explicacion anterior solo es posible para los metodos lock() y unlock()). Como el metodo tryLock() no pone el hilo en reposo si se utiliza la interfaz Lock, el atributo fair no afecta su funcionalidad.

¡Advertencia!
Tener cuidado con los bloqueos para evitar InterBloqueos (Deadlocks). Ocurren cuando los hilos se quedan esperando por bloqueos que nunca se liberarán. Por ejemplo: El Hilo (A) obtiene el bloqueo (X) y el Hilo (B) obtiene el bloqueo (Y). Luego, el Hilo (A) intenta obtener el bloqueo (Y) (que ya tiene B) y al mismo tiempo el Hilo (B) intenta obtener el bloqueo (X) (que ya tiene A). Como ninguno suelta su bloqueo hasta conseguir el otro, ambos se quedan esperando infinitamente.
